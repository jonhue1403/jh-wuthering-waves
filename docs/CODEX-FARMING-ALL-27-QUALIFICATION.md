## Replay and limits

`TestFarmingAll27Replay` tests the real planner, stop policy, goal queue and journal. Across all 27 it checks reference-only plans, absent source, no-growth and wrong-item refusal, partial progress, target reached, and attempt exhaustion. Overworld and domain candidates also have synthetic available, unqualified, ambiguous, stale-runtime, missing-profile and wrong-item mappings. Synthetic `READY` is a mapping result only. For applicable material/provider families the journal refuses an insufficient balance, rejects mismatched account/cycle and duplicate retries, and reconciles once with synthetic evidence. An interrupted material activity survives a reopen and cannot immediately be rerun.

`TestMaterialRoute` uses the existing bounded controller with synthetic navigator, pickup and inventory readers for each mob-reference item. It tests verified synthetic gain, no drop despite pickup attempts, wrong item, cancellation/cleanup, timeout and stale profile rejection. Each item uses a shared route shape, not an actual material-to-enemy route. Combat clear, pickup invocation, reward confirmation, matching inventory growth and target completion are distinct outcomes. The route tests cover navigation and stop semantics; the journal tests cover state recovery without claiming to run a cancelled live task.

The isolated domain selectors and task tests exercise invalid indices, adapter refusal, identity, resource/journal controls and receipt handling. Exact current challenge mappings, UI reward recognition from real captures, session authorization and reset/account proof are missing. There is no native synthesis execution adapter in the Farming Assistant; all relevant material tests assert reference-only conversion and no execution. Recipe details, ingredient counts, conversions and post-synthesis behavior were not verified. Manual/event/historical sources pass by remaining blocked; their true availability is unknown unless otherwise noted by an official announcement.
